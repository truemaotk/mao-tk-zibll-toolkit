# 系统邮件外观（1.20.0）

安装独立插件 ZIP 后打开 **Mao TK Toolkit → 系统邮件外观**。模块默认关闭，先核对设置再开启。升级保留已有明确开关及配置。本指南不表示作者网站已经部署或邮件投递已验收。

## 模板与继承

通用设置控制邮件专用 PNG Logo、尺寸与对齐、配色、内容宽度、圆角、字号、段落间距、按钮和页脚。每类邮件可使用通用模板、单独覆盖或原生样式；未覆盖字段继承通用。合法空字符串和 0 是明确覆盖。切换模式不会删除独立配置。

九类通知适配已核对的 Zibll 9.2／WordPress 入口：操作验证码、找回密码验证码、账号创建通知、密码重置链接、买家付款通知、商家待发货、买家发货、虚拟商品交付、售后处理结果。售后结果不等于退款已到账。没有原生事件的类型不会为了模板增发邮件。

## 客服回复

“客服与回复”可配置回复邮箱和客服名称。接管邮件的 Reply-To 使用该地址；原收件人、From、Cc、Bcc、附件和 SMTP 保留。邮箱留空时保留原 Reply-To。页脚 mailto 是撰写新客服邮件，客户端“回复”才使用原邮件线程。

仅 maotk.com 和 www.maotk.com 尚未配置的新字段默认使用用户指定的 support@maotk.com／Mao TK 客服。其他域名不使用作者的回复邮箱。已有明确值或显式清空值不会被升级覆盖。

## CNY 与真实数据

人民币可选择 CNY 显示，保持原金额字符串和精度，不换算汇率。明确外币、积分、URL、代码与虚拟交付内容保持。其他网站的币种显示默认沿用原系统。

标题、正文和按钮支持后台按类型列出的真实变量。预览和主动测试使用变量结构，不填假验证码、用户或订单；正式业务发送才填入真实数据。结构预览不会提供虚构的订单操作链接。

## Logo 与邮件交互

独立上传或填写高清 PNG 地址，建议显示 120px 时使用至少 240px 宽原图。默认顶部左对齐，可改位置和尺寸。没有图片则显示真实站点名称，不影响导航 Logo。

邮件使用表格、内联 CSS、系统字体和原生链接；不使用网站 JS、折叠或网页动画。验证码可选取／长按复制；业务按钮使用原系统链接，并在需要时显示可复制的网址。

## 测试与回退

用户主动点击才发模板测试邮件，主题含 [测试邮件]，有明确说明，保持发送间隔限制。模板测试不生成实际验证码、账号或订单。wp_mail 接受不等于最终到达，仍需自行收件验证。

关闭模块或按类型选择原生即可恢复原外观，设置保留。未知来源、未适配版本、完整 HTML、WooCommerce 与 Order Email Manager 等自有模板避免二次包装。验证码生成、有效期、频率、注册、订单状态与 SMTP 继续由原系统负责。

可在“配置导入&导出”单独备份系统邮件设置。恢复前先预检和比较，不导入任意网站选项、SMTP 或订单；模块开关默认不随配置恢复。

## 验收范围

本地 WordPress 7.1.4、PHP 8.5.12、SQLite QA 环境，结合真实 Zibll 9.2 通知函数契约，通过 68 项原生邮件、65 项回复／币种／继承、69 项浏览器和 54 项配置备份测试。124 个生产 PHP 文件语法检查通过，ZIP 有 674 个文件。

本地测试拦截对外邮件；浏览器验证不替代完整生产主题、MySQL、SMTP 和 Gmail／Outlook／QQ／163 真正收件验收。部署者应先备份，再在自己的测试邮箱和受控业务流程中验证。
