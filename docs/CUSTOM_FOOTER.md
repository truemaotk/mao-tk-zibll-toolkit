# 自定义页脚

Toolkit 1.22.0。模块 ID `site-custom-footer`，设置键 `mao_tk_toolkit_custom_footer`，默认关闭。

## 安装与启用

1. 在 WordPress「插件 → 安装插件 → 上传插件」上传 **mao-tk-zibll-toolkit-1.22.0.zip**，已有 Toolkit 时确认替换当前版本。先保留网站备份。
2. 打开「Mao TK Toolkit → 页脚设置」。先填写并保存内容；也可点击「读取主题资料」将能识别的原生介绍、版权文字和二维码读入未保存草稿，再自行核对。
3. 调整三个导航栏目、微信/WhatsApp/Telegram/GitHub/邮箱入口、二维码、版权与备案。标题可自行修改，不自动插入隐私政策等链接，也不显示关于区 Logo。
4. 社交图标支持媒体库或 HTTP(S) 图片地址、恢复本地 Tabler 图标。大小 12–32px；底座可关闭；仅用 0–24px 圆角滑条，0px 为直角。关闭底座保留点击区域和圆角设置。
5. 在桌面/手机、明暗预览中检查，保存后开启「自定义页脚」。在实际前台刷新核对。图片自身的透明留白不会自动裁切。
6. 「布局与继承」可选跟随页眉或全宽。栏目与版权栏共用同一宽度，背景铺满页面。桌面二维码左侧对齐标题，手机关注区居中。
7. 在「关注我们与二维码 → 统一边框」调整显示、1–4px 粗细和 0–24px 圆角。桌面版权和备案分列，版权栏上方使用细分隔线。

本模块随 Toolkit 安装，不再额外安装一个独立页脚插件。**GitHub 的自动 Source code ZIP 是整个仓库，不是插件安装包。**

## 行为与边界

- 手机端关于与关注区常显，关注区在菜单/友链之后、版权之前；有效菜单和友链使用共用 380ms 真实高度折叠，遵循系统减少动态效果。
- 空社交入口、空二维码和无有效链接的导航列不在前台生成空白占位；不附带作者的账号、客服邮箱、二维码、备案号或样板图片。
- 读取 WordPress `get_bookmarks()`，保留现有友情链接可见性筛选；不修改链接记录、推荐参数或账号权限。
- 关闭模块后，不再注册页脚接管，恢复子比原生页脚；原始主题设置与页脚小工具保存值不删除。其他 Toolkit 模块及已验收邮件不改。
- 独立 option 和管理员/nonce 校验；预览不保存，保存比较 revision，过期窗口不能覆盖新设置。媒体由 WordPress 媒体库负责，本模块不提供公开上传接口或服务端 URL 抓取。
- 可在「配置导入&导出」选择“自定义页脚与社交图标”连同本地图片迁移。模块开关仍需主动勾选恢复。页面内“导出配置”仅导出当前页脚 JSON 便于审阅，正式跨站恢复使用配置导入&导出。

## 接入依据

已核对用户提供的 Zibll 9.2：`footer.php` 中 `dynamic_sidebar('all_footer')`、`do_action('zib_footer_conter')` 和 `wp_footer()`；`inc/functions/zib-footer.php:575` 注册原生 `zib_footer_con`。

在真实 `get_footer` 阶段验证目标模板结构后，当前请求隐藏 `all_footer` 小工具输出并替换已知原生内容回调，仍保留外层 footer 和 `wp_footer()`。在 `wp_footer` 最早阶段恢复临时筛选和原回调。组件外层为 div，避免 footer 嵌套。CSS bridge 仅作用于包含本组件的原生 footer，未输出组件时不改变原生结构。不修改主题文件，不使用全页输出缓冲或移除其他 wp_footer 回调。

当前仅核对 9.2 系列的上述模板合同；非 Zibll、未识别的模板或无效配置保留原生输出，后台显示提示。子主题提供 footer.php 时同样需满足合同，不因子主题目录名不同而拒绝。主题升级或自定义模板后需再次核对。

## 验证与许可

本地 PHP 8.5.12、WordPress 7.1.4＋SQLite、真实 9.2 页脚文件与样式的合同夹具：20 项集成检查、17 项浏览器检查通过。覆盖保存、过期请求、媒体库、nonce/匿名拒绝、空项目、手机宽度和折叠、模块关闭回退。夹具不是完整商业主题环境；用户自行上传后应按本节实际站点验收。
