# 正文提示框 · Toolkit 1.5.10

视觉基线：用户封板 **1.0.0**；原区块提供者基线：**maotk/note 1.0.4**；本次宿主适配：**1.0.1**。这不是独立新插件或 Skill，也不是文章时效提示／主题系统通知。

## 启用、共存与接管

进入 **Mao TK Toolkit → 正文提示框**。也可从“文章 UI 组件”说明区进入。

1. 未设置提供者时默认 **Toolkit 接管**，仅在没有活动原插件且不存在同名块时注册。原 1.0.4 插件处于活动状态并成功注册时，仍由它唯一提供，Toolkit 只增加外观设置与编辑器控件。已有明确的“沿用原插件”选择保持，不强制改写。
2. 确认要由宿主提供时，选择 **Toolkit 接管（原插件未启用时）** 并保存。此后 Toolkit 注册原名 `maotk/note`。它不自动停用原插件，也不强行 unregister 已有区块。
3. 重新启用原插件时，新请求会优先保留原插件的唯一提供者，Toolkit 不再加载第二份 provider.js。未知提供者、无法安全适配的结构或依赖不足时停止接管并显示原因。
4. **外观增强** 是独立开关，未设置时默认启用，明确关闭时保持。关闭后仍保存配置、可后台预览；已经明确选择的基础提供者和旧区块基础编辑不随此外观开关消失。基础样式保留原插件效果。

最低新能力门槛为 **WordPress 6.3、PHP 7.4**，对应原插件的 apiVersion 3。实际本地 PHP 检查使用 8.5.12，没有全版本兼容认证。基础提供者为保留内容编辑不依赖 Zibll；新外观由模块机制要求父主题目录 `zibll`，允许子主题。整个 Toolkit 停用且原插件也停用时，保存 HTML 仍在，但编辑器缺少原块提供者，不能宣称仍有完整编辑能力。

## 配置继承与恢复

有效值顺序：**封板类型基线 → 模块通用覆盖 → 类型覆盖 → 单区块显式覆盖**。留空／“继承”表示没有覆盖，合法 false 不会变成 true。普通文章默认继承后台，不为调整对比度擅自写入单块颜色。后台已保存但某篇不变时，先检查该块的 maoTkNoteVisual.light/dark；需要恢复后台控制时仅清除对应颜色字段，保留位置、图标等其他配置。

| 字段 | 允许值 | 封板默认 |
| --- | --- | --- |
| 浅／深色 | 完整 `#RRGGBB` | 见下表 |
| 标签位置 | left / center / right | left |
| 图标位置 | before / after | before |
| 图标 | 注册表内稳定 key | 按类型 |
| 图标尺寸 | 整数 12–28px | 16px |
| 显示图标 | 显示／隐藏 | 显示 |
| 内部标题颜色 | type / neutral | type |

| 类型 | 浅色 | 深色 | 图标 |
| --- | --- | --- | --- |
| info 说明 | #a54d08 | #ffb76f | info |
| primary 提示 | #285fa2 | #97c2ff | lightbulb |
| success 推荐 | #1b7451 | #80dab2 | circle-check |
| warning 注意 | #8c620e | #efcd78 | triangle-alert |
| danger 风险 | #aa3542 | #ffacb5 | shield-alert |

后台颜色使用本地 PS 式二维调色盘：拖动饱和度／明度色板、调整色相滑块，也可输入 HEX、选择封板预设色或逐色恢复继承。浅深色并排显示，共用一个弹出面板，不额外加载 WordPress 的 wp-color-picker。色板支持触屏拖动、方向键微调、Shift 加速、Esc 关闭并回到原色块。编辑器继续使用原生 `ColorPicker`。固定六位颜色契约不接收任意 CSS 或透明度字符串。后台尺寸有数字输入与滑块；编辑器使用 RangeControl 的滑块和输入。

### 后台布局与预览

1.5.1 将长折叠表单改为“通用、说明、提示、推荐、注意、风险、接入”标签。方向键切换相邻标签，Home／End 到首尾；切换时保留所有未保存输入。保存后回到原标签，隐藏标签中的非法字段会自动展开以便修正。接入选择和页面范围集中在“接入”中。

预览默认跟随当前类型，可切换“全部”对照五种类型；桌面／手机与浅色／深色独立切换。手机预览使用最多 390px 画布和手机字号。拖动与输入只同步本地预览，只有“保存设置”提交正式配置；页头“已同步／未保存”区分当前编辑状态。界面继承 WordPress 管理员配色和字体，窄屏上下排列。JavaScript 不可用时显示全部表单，仍可手填 HEX 并原生提交。

后台“恢复继承”移除当前组覆盖；颜色旁“继承”仅清除此色。“恢复封板默认”清空全部外观覆盖，保留提供者和页面范围。操作先更新预览，点击保存后才影响正式页面。编辑器“全部恢复继承”删除 `maoTkNoteVisual`；“使用封板默认（单块覆盖）”明确保存当前类型的封板值，以后不随全局设置变化。

原 `showBadge`／`showTitle` 开关继续在旧提示框设置中，不复制第二套。标签 badge、标题 title 的空值与历史 RichText 保留。图标仅在存在标签的布局内显示，隐藏图标无占位；位置只是框内排布，不是全站悬浮插入位置。

## 内容与作用域

- 保留名称、五个原属性、原始 edit/save、anchor、wide/full 支持声明，以及原 InnerBlocks 的段落／列表限制；只加稀疏对象属性 `maoTkNoteVisual`，不改变 save 输出。
- 前台使用 `render_block_maotk/note` 对当前块根 aside 添加受控 CSS 变量与数据属性，不更新数据库，不批量写文章。标题仍为 `div.maotk-note-title`，文章 h1–h6、子比标题和目录保持原生。
- 不要求 `.maotk-ui-kit`。提示框不会因为文章里无关 style/script 而整体跳过；也不删除旧专项样式。旧提示框自定义 CSS 若覆盖本次效果，须在草稿中逐项盘点处理。
- 原四组件的包装与旧资源避让规则保持原样。没有新增下载、付费、商品、账户或鉴权逻辑。
- 默认只增强普通文章；后台明确选择后可增强页面。本地替身已覆盖页面选择，真实页面、嵌套组、模板和同步内容仍须目标站验证。
- CSS 依次使用原基础层、带增强标记的封板层、受控配置。前台不需要本模块 JS；多实例共用资源句柄。编辑器和后台资源按对应界面加载，不引入全页观察器。

## 已实现的维护接口

配置保存在已有 `mao_tk_zibll_toolkit_settings`、顶层 schema_version 1 中：`article_note` 是可验证的视觉配置，`article_note_provider` 独立保存明确的区块提供者意图。视觉子配置损坏不抹掉已选择的基础提供者。未改 `zibll_options` 或既有独立模块的 option。

| 接口 | 实际位置／约定 |
| --- | --- |
| 模块 ID | `article-note`，ModuleManager 注册 |
| 配置解析 | `ArticleNote\Settings::resolve($type, $settings, $override)`，仅返回受控有效字段 |
| 前台呈现 | `render_block_maotk/note` 优先级 10，接收内容和 parsed block，保留内容节点 |
| PHP 属性注册 | `register_block_type_args` 优先级 10，仅已识别原提供者／自身提供者；保留原属性 |
| 编辑器 | `blocks.registerBlockType` 添加覆盖属性；`editor.BlockEdit` 补控件；`editor.BlockListBlock` 只传展示 wrapperProps；不改 save 过滤器 |
| 图标扩展 | `mao_tk_zibll_toolkit_note_icons`，输入／输出新增条目的关联数组，初始为空；见下例 |
| 图标解析时机 | 当前请求首次读取配置／初始化时缓存，扩展需在插件加载阶段或 after_setup_theme 优先级 20 之前挂好过滤器 |

```php
add_filter('mao_tk_zibll_toolkit_note_icons', function (array $icons): array {
    $icons['my-reviewed-icon'] = array(
        'label' => '自有本地图标',
        'file' => 'assets/custom-icons/my-reviewed-icon.svg', // 相对 Toolkit 根目录
        'viewBox' => '0 0 24 24',
    );
    return $icons;
});
```

文件须预先审核并随 Toolkit 构建纳入发布清单；此接口不提供上传、下载或执行脚本能力。只允许插件内部真实本地 SVG、最大 32KB、24×24 viewBox、被允许的静态 SVG 标签，不允许远程 URL、目录穿越、外部 href、事件、DTD 或脚本。八个默认 key 不允许被扩展覆盖，重复／无效项忽略并在后台说明。后台只列成功条目。已存 key 对应文件丢失／扩展移除时回退到类型默认；HTTP/CSP/浏览器屏蔽造成的图片请求失败仍需环境排查，不声称自动修复服务器资源策略。

## 验证和回退

本地完成配置读写、非法输入、注册所有权、原 save 树对比、PHP/JS 解析一致性，以及浏览器布局／预览／开关检查。1.5.1 另以本机 Chrome 验证后台调色盘真实鼠标／触屏拖动、键盘操作、标签值保留、无 JS 后备、配色继承及 320／390／960／1280／1920px 布局。**没有真实 WordPress/Gutenberg、数据库或 Zibll 环境。** 原文“打开→保存→重开”、编辑器区块校验及原生调色盘、iframe 编辑画布、当前主题暗色／PJAX、同步区块、真实旧文章和 anchor/align 往返均待验。替身不能证明这些项目通过。

没有真实文章导出，未迁移或修改任何文章。上线前先备份当前旧插件与正文，在独立草稿按上述项目验收。

回退先关闭外观增强并保留块提供者；需要退回旧独立插件时，恢复旧插件包、选择沿用原插件，确认无覆盖属性依赖后再停宿主。若新文章包含 `maoTkNoteVisual`，旧插件不识别该扩展，应先备份并在草稿检查旧版本往返，不批量删属性。退回 Toolkit 1.4.0 本身不提供 note：务必保留原插件，否则编辑器会缺块；不要删除整个 Toolkit option 或正文来回退。
