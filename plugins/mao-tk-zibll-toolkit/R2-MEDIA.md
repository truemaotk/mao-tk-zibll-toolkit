# R2 图片同步

Toolkit `1.24.0-rc.1` 新增独立模块，默认关闭。WordPress 继续存放原图和生成的尺寸。模块把已识别的图片同步到私有媒体桶，再按前台输出切换图片地址。正文内容、媒体记录和下载模块各自保留。

## 配置顺序

1. 使用已有的私有 `maotk-site-media`，在 Cloudflare R2 新建仅限此桶的 Object Read & Write S3 凭据。复制 Account ID、Access Key ID 和 Secret Access Key。 [Cloudflare 凭据说明](https://developers.cloudflare.com/r2/api/tokens/)
2. 打开「Mao TK Toolkit → R2 图片同步」。填写媒体桶和凭据、`https://maotk-media.todinjone.workers.dev`，以及与媒体 Worker 的 `MAOTK_MEDIA_SIGNING_KEY` 一致的密钥。先保持前台地址切换关闭。
3. 在 `maotk-media` 的生产环境确认 `MEDIA_BUCKET` 指向媒体桶，并将文本变量 `MAOTK_MEDIA_WP_ORIGIN` 设为 `https://www.maotk.com`。WordPress 需支持 `/wp-json/` 路由。
4. 点击「测试媒体连接」。后台上传一张测试 PNG，经签名 Worker 地址读回并核对字节，随后清理测试对象。这个检查验证读写与签名。缺图回源和恢复需要另外用测试附件验证。
5. 开启「自动同步」。可让访客打开带媒体库图片的公开文章，或点击「仅补传未同步」。先确认对象已写入媒体桶。任务依赖 WP-Cron 或站点的系统计划任务。 [WP-Cron 执行机制](https://developer.wordpress.org/plugins/cron/)
6. 小范围验证 R2 缺图和 WordPress 本地缺图的恢复后，为 `maotk-media` Worker 绑定 `media.maotk.com`。更新插件中的 Worker 地址，重新点「测试媒体连接」，再勾选「启用前台地址切换」。清理受影响页面的整页缓存后用未登录窗口检查。

从 `1.24.0-rc.2` 开始，新批量任务显示实时扫描、已排队、已处理及失败数量。有足够样本后显示预计剩余时间，持续 90 秒无进展时显示等待后台。上一版启动的任务沿用原队列，只显示已有的排队数据。

从 `1.24.0-rc.3` 开始，新建批量任务可在「历史图片」中暂停和继续。正在处理的文件结束后暂停，继续时从保存的位置处理下一个文件。旧批次按原有方式处理。批量任务每轮处理一个图片文件，处理结束后至少间隔 10 秒。站点的 WP-Cron 触发频率决定实际间隔。

从 `1.24.0-rc.5` 开始，批次最多连续处理 20 个文件步骤，运行满 8 秒后不再开始下一个文件。正在处理的请求仍使用各自的超时。原有批次保留当前文件位置和暂停状态，原有完整核对模式也继续适用。WordPress 媒体库或编辑器上传的新图在保存附件信息时优先入队。

- 「仅补传未同步」跳过已有同步记录且本地文件大小、修改时间均未变化的文件，适合首次迁移和日常补传。
- 「完整核对」逐文件核对 R2 对象，修复只剩本地或只剩 R2 副本的情况。主动从 R2 删除对象后，可以用此模式检查和恢复。
- 低流量站点可在服务器为本站配置 WordPress 定时任务。先核对现有任务，避免重复。宝塔可先用每分钟执行一次的 Shell 任务，通过 HTTPS 访问本站的 `/wp-cron.php`。保存后，在关闭同步后台页面的情况下确认任务进度仍会更新。 [WordPress 系统任务配置](https://developer.wordpress.org/plugins/cron/hooking-wp-cron-into-the-system-task-scheduler/)

连接中断、限流或 R2 服务端错误会在 30 秒和 60 秒后重试当前文件。连续三次失败后记录该附件的失败，并至少等待 120 秒再处理剩余文件。R2 拒绝凭据或报告目标不可用时，批量任务暂停在当前文件，修正连接配置后可继续。变更存储桶会中断原批次，需要针对新桶启动任务。

## 工作方式与范围

- 第一次访客访问时，未同步的本地图照常展示，附件进入后台队列。已同步且连接验证通过的公开图片，后续生成的 HTML 才使用 Worker 地址。
- 首版在未登录的公开 HTML 中处理可匹配到媒体库的 `img`、`picture source`、`srcset`、子比 `data-src`、`data-srcset` 和 `box-img`。外链、CSS 背景、JS 后加载片段和未能匹配到媒体附件的文件继续走原路径。预览、受密码保护的文章、后台和登录态前台沿用本地图。
- 支持每文件 16 MiB 以内的 JPEG、PNG、WebP、GIF、AVIF。地址切换需要 WordPress 的 `WP_HTML_Tag_Processor`（6.2 起）。连接加密需要 OpenSSL 与独立密钥或可用的 WordPress 认证密钥。
- 同一配置重测失败时会保留上次通过记录，并显示本次错误。修改媒体桶、账户、地址或密钥后，新的配置须通过测试才会切换前台图片地址。
- 轮换 WordPress 安全密钥前，在「R2 图片同步 → 连接设置」使用「迁移已保存凭据」。服务器密钥的设置顺序见 [R2 下载指南](R2-DOWNLOADS.md#迁移后台已保存的-r2-凭据)。
- R2 展示图缺失时，Worker 通过签名请求从 WordPress 读取现存本地图并触发补传。WordPress 本地文件缺失时，后台使用存储记录校验并从 R2 恢复到原路径。恢复需要原上传目录仍存在、可写且支持原子文件链接。原图单独保存在 `original/`，公共图片 Worker 只读 `public/` 且检查图片签名。
- 从媒体库永久删除附件后，会排队移除对应的展示对象，保留原图副本。自动恢复适用于附件记录仍在的情况。附件记录被删除后需人工重新导入，当前未提供一键恢复附件记录的页面。
- 缓存命中期间可能延迟发现 R2 误删或继续显示本地地址。后台巡检会检查已记录的对象，首次切换时也应核查整页缓存。签名图片是公开展示资源，拿到已发布地址的访客可分享它。

## 本地验收

使用 WordPress 7.1.4、PHP 8.5.12 和 SQLite 运行集成测试，R2 和 Worker HTTP 请求均用本地响应模拟。验证了连接测试、旧图排队、尺寸及原图同步、响应式与懒加载地址切换、签名回源、两侧缺图恢复和批量任务。真实 Cloudflare 读写、缓存配置和生产站点尚待联调。
