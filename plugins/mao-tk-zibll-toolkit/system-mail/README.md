# 系统邮件外观（1.20.0）

独立模块 `system-mail-appearance`，默认关闭。入口为 **Mao TK Toolkit → 系统邮件外观**。正式安装包已生成，未替换生产站插件、未推送，也未修改教程。真实邮箱客户端收件仍需部署后的投递验收。

## 客服回复、CNY 与上线配置

“客服与回复”中可填写单一客服邮箱和显示名称，支持通用继承／类型独立覆盖。填写后仅对本模块接管的邮件替换 Reply-To，保留原收件人、From、Cc、Bcc、附件和 SMTP 配置。留空保留原 Reply-To，不显示专属客服入口；独立配置中的空字符串也是明确设置。

页脚提供客服 mailto。收件人用客户端的“回复”会发到 Reply-To，并由客户端维护邮件线程；点击 mailto 是撰写一封新客服邮件，不模拟原邮件线程。原生模式、关闭模块、未知来源与第三方完整模板不强行改回复地址。旧默认的“请勿直接回复”只在已启用客服回复且文案仍完全等于旧默认时自动改为中性文字；其他自定义页脚保留。

`maotk.com` 和 `www.maotk.com` 是用户授权的部署域名：未配置的新字段默认回复 `support@maotk.com`、名称 `Mao TK 客服`，人民币显示 CNY。不会覆盖已有明确设置或显式清空值，不匹配其他子域或其他网站。其他域名默认回复邮箱为空、币种沿用原系统，避免将其他站点邮件导向本站客服。模块全局开关不自动打开。

CNY 选项只替换可识别的人民币标识，保留金额原字符串和精度，不换算汇率；外币和积分保留。原订单明细中可识别的人民币文本同步规范化，URL／代码及虚拟交付内容不改写。币种标记／单位明确为其他币种时不冒充人民币。

邮件专用 Logo 默认位于顶部左侧，仍可选择左／中／右及宽度。请上传高清 PNG，例如显示 120px 时使用至少 240px 宽原图；未上传时显示真实站点名称，不使用虚构 Logo。不会修改导航 Logo。

升级后进入本页核对设置，按需开启外观模块。本站已准备的可选配置包可通过“配置导入&导出”恢复，仅含邮件模板，不包含模块开关、SMTP 或订单数据。

## 当前邮件版式

1.20.0-rc.2 只更新渲染器外观，不更改已保存配置、来源识别、变量目录、校验、发送或原生回退。

- 通用外壳：邮件专用品牌区、轻边框正文、明确标题与独立页脚。辅助底色和次级文字由当前设置配色派生，用户自定义的浅／深背景可继续使用。
- 操作验证码与找回密码验证码：说明先于验证码，验证码与实际有效期居中显示；长验证码可以自然换行。
- 账号创建与密码重置链接：突出对应账号及原生操作入口，不新增发送或构造密码令牌。
- 付款通知：强调真实订单金额；商家待发货和售后结果强调原通知状态；买家发货与虚拟交付强调订单号。金额保持原业务文本，不补写币种或宣称退款到账。
- 虚拟交付：原始交付区域以细色条区分；没有原生操作入口时不制造额外按钮。
- 操作按钮使用适合手指点击的整行入口；宽度、圆角、颜色、字号和文案仍取现有设置。原始主操作的地址不变。
- 采用流式 table、内联 CSS 和系统字体；不加载网站前端资源、外部字体或动画。桌面和手机预览都使用这同一渲染器。

真实通知详情不因文案定制而丢弃。订单摘要与原始通知中可能存在相同字段，原明细保留，避免误删物流、付款细节或交付凭据。

## 配置与继承

通用模板包含邮件专用 PNG Logo、显示宽度与对齐、主题色／背景色／正文色／边框色、内容宽度、圆角、标题／正文字号、上下间距、内边距、段落间距、按钮及页脚。

每类邮件可选“通用模板／单独配置／原生样式”。单独配置只保存勾选字段，其余实时继承通用；有效的 `0` 和空文案属于明确覆盖。切到通用或原生时不删除独立配置。分类标题显示继承概况，各字段显示“独立设置／继承通用”。

邮件 Logo 独立存入本模块，可从媒体库选 PNG 或填写 HTTP(S) PNG 地址；建议原图宽度至少为显示宽度两倍。不写入 `zibll_options`，不修改导航 Logo，不自动下载、转换或重新压缩原图。

文案支持 `{{variable_name}}`。后台按邮件类型提供真实变量，未支持变量在服务端拒绝保存。通用模板只允许跨类型通用变量；验证码和订单数据不能写死在运行时模板中。无原生业务入口的验证码／虚拟交付类型不凭空增加操作按钮。页脚链接支持完整 HTTP(S) 地址或 `{{site_url}}`。

自定义开头若省略 `{{original_content}}`，原通知详情仍自动附在后面，避免遗漏密码链接、物流、支付明细或虚拟交付内容。原始主操作链接会被同地址的新按钮替换一次，其他链接保留；按钮文案留空时保留原始入口。

## 已适配来源

以用户提供的 **Zibll 9.2** 源码为契约。其他版本保留原生运行时外观，设置和示例预览仍可用。

| 邮件类型 | 原始来源 | 动态内容 |
| --- | --- | --- |
| 操作验证码 | `zib_send_captcha` | 从原通知提取真实验证码和有效期；识别失败回退原生 |
| 找回密码验证码 | `zib_ajax_resetpassword_captcha → zib_send_captcha` | 同上，原发送限制和校验不变 |
| 账号创建通知 | `wp_new_user_notification_email` | 用户名、显示名、原始设置密码入口 |
| 密码重置链接 | `retrieve_password_notification_email` | 原始重置链接与用户信息 |
| 付款成功（买家） | `zibpay_mail_payment_order` | 原订单号、有效支付金额、通知状态、商品、详情入口 |
| 待发货（商家） | `zib_shop_notify_shipping_to_author` | 订单资料、待发货或原通知的异常信息、管理入口 |
| 发货通知（买家） | `zib_shop_manual_shipping_to_user` | 原金额、物流单号、公司、备注及订单入口 |
| 虚拟商品交付 | `zib_shop_virtual_shipping_to_user` | 原订单及交付内容；不额外构造下载权益 |
| 售后处理结果 | `zib_shop_after_sale_to_end_to_user` | 原处理结果、金额、原因、处理备注及入口 |

验证码、有效期来自原邮件，而非后台可编辑的业务设置。原 `zib_send_captcha` 继续生成验证码、存哈希、设有效期及限制频率。本模块不监听 `user_register` 增发欢迎信；子比前台注册未发现独立欢迎邮件，只适配原本实际发送的 WordPress 账号通知。

“售后完成”不等于“退款已到账”。未付款下单、独立退款到账邮件、管理员支付提醒、佣金、评论、私信等本轮未适配，保留原生，不新增发送。WooCommerce／Order Email Manager 的完整 HTML、自有邮件类及 multipart 邮件排除，避免第二层模板。

## 邮件过滤边界

1. 模块启动时移除子比 `wp_mail` 上的 `zib_get_mail_content`（原优先级 10），以本模块同优先级回调接手外层包装；`init` 999 再核对迟注册包装器。
2. 已识别的邮件按保存模式渲染。未知来源、原生模式、无效设置或未核对的主题版本调用原包装器；完整 HTML／第三方完整邮件在启用时透传。
3. WordPress 账号／重置 hooks 在 `PHP_INT_MAX` 只捕捉本请求上下文，原值原样返回。订单参数从已核实通知函数的当前调用参数读取，无查询／改写订单状态。
4. 不接管 SMTP、`phpmailer_init`、From 配置、验证码存储、发送频率、注册和订单事件，不增加定时任务。渲染失败回退原邮件，不保存或记录真实验证码、密码令牌、交付凭据或邮件正文。
5. 开关关闭后原过滤器照常工作，设置保留；同请求关闭也回退原包装器。原生模式确实沿用主题原逻辑，包括它原有的主题前缀及 headers 处理。新模板替换 Content-Type；仅填写了专属回复邮箱时替换 Reply-To，保留收件人、From、附件、Cc、Bcc。未填写时原 Reply-To 保留。

## 后台预览和测试

预览使用正式模板变量，例如 `{{code}}`、`{{order_number}}`、`{{amount}}`，不填虚构验证码、客户或订单，不读取真实客户数据。切换桌面／手机，不触发验证码生成、注册或订单变更。订单动作在结构预览中为不可操作占位；实际业务邮件才使用原系统真实链接。预览 iframe 不允许脚本、弹窗或跳转；未保存设置只用于本次预览。客服回复地址在预览上方明确显示。

用户主动点击“发送测试邮件”才调用原 `wp_mail`／SMTP，主题带 `[测试邮件]`，正文标明“模板测试邮件”，每位管理员间隔至少 60 秒。测试也使用变量结构，不放示例金额或假验证码；使用当前设置，包括未保存内容，按钮不会保存配置。`wp_mail` 接受不代表最终投递，实际到达与客户端效果仍需收件验证。

正式邮件不依赖脚本交互：验证码可选中或长按复制；原生业务按钮打开原入口，必要时附可复制的网址；页脚邮箱打开客户端撰信。支持 CSS 的客户端增强选取反馈，不支持时仍可正常选择文本。不会在邮件中加入网页折叠、弹窗或 JavaScript。

接口需要 `manage_options`、POST 和 nonce。保存使用 revision 防止旧页面覆盖；无效配置暂停写入并保留原值。预览异步请求取消过时响应；保存／测试期间锁定编辑，避免提交中修改被响应覆盖。

## 数据与维护

- 设置 option：`mao_tk_toolkit_system_mail`，schema `version: 1`。
- 模块开关仍在 Toolkit 管理器的独立键；不改其他模块值。
- AJAX：`mao_tk_toolkit_system_mail`，operations `read / save / preview / test`。
- 后台资源仅在本模块页加载：`assets/system-mail/admin.js`、`admin.css`。
- 核心代码：`inc/system-mail/`；独立注册器 `inc/modules/class-system-mail-module.php`。
- 本模块无文章前端资源，无主题文件覆盖，无第三方依赖新增。
- 停用不删除设置；模板和独立配置可通过 Toolkit 的“配置导入&导出”分类备份。没有一键删除配置功能。

邮件为流式表格、内联 CSS、系统字体与 Outlook 宽度条件表格。不依赖网页 CSS／JS。圆角、断词等客户端表现可能不同；本地浏览器验证不等于 Gmail、QQ、163、Outlook 真机收件验收。
