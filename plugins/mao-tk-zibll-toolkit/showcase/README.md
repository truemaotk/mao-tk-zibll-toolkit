# 页面组件 · 案例展示

Toolkit 1.6.4，视觉基线为用户确认的独立样板v0.4。新功能是中央案例库和页面引用；没有把样板的Node服务、本地存储、模拟编辑器或整页HTML搬进WordPress。1.6.3起列表底部不再显示重复的长图说明，图片操作提示仍可通过原设置控制。

## 管理与创建页面

1. 在 **Mao TK Toolkit → 案例展示** 管理案例。左侧“管理案例分类”可新增、改名、移除分类。
2. 添加案例，填写名称、说明、分类、网站地址和两个按钮；图片通过WordPress媒体库选择。案例可属于多个分类，“在前台展示此案例”关闭后只保留在管理器中。
3. 在“样式”设置两枚按钮图标、统一大小、浏览器窗口、列数、间距、圆角和浅深色。图标可上传SVG/PNG/JPG/WebP，或填写公开图片链接并应用；512KB以内，导入后使用本地媒体附件。
4. 点击 **保存案例库**。当前未保存修改只影响管理器预览；保存后，新请求的关联页面读取统一资料。整页缓存/CDN需按站点缓存机制刷新。
5. 打开 **页面 → 新建页面**，填写原生页面标题，在右侧“模板”选择 **MaoTK 案例展示**，再在“MaoTK 案例展示”面板选择案例分类。选择“全部案例”可展示整个启用案例库。
6. 预览并发布。正文可留空，或写一段原生介绍。模板会自动在正文后输出案例；不用再插入区块、短代码或CSS/JS。

页面模板使用WordPress标准模板列表登记，继续由当前主题的页面模板渲染页头、原生标题、内容容器和页尾。无需复制PHP文件到主题。页面如果本身已插入案例区块或短代码，明确插入的位置优先，模板不再重复输出第二份案例。

## 页面宽度与主题

- “样式 → 模块上下留白”可分别设置上方、下方间距，各0—200px，默认10px。调整的是整个案例区域的上下留白，不改变卡片内部间距；后台预览即时变化，保存后应用到关联页面。
- 数据字段为`settings.sectionPaddingTop`、`settings.sectionPaddingBottom`，均为整数。旧配置缺少时取10；0是合法值，不回退为默认数值。沿用schemaVersion=1，不主动覆盖旧库。

- 默认“跟随页面容器”：模块宽度100%，不重置全站容器、侧栏、页头或其他组件。
- 选择“自定义最大宽度”后才额外限制模块，720—1440px。
- 页面实际宽度仍受主题页面布局和侧栏设置影响。若希望作品集占满可用区域，请使用主题提供的无侧栏／宽版页面设置。
- 自动浅深色跟随Zibll的`dark-theme`类；也可固定浅色或深色。
- 字体继承主题／WordPress系统字体；默认Lucide图标随插件本地打包，没有字体或图标CDN。

## 日常编辑

- 拖动左侧手柄排序；有跟手卡片、落点线和220ms重排。聚焦案例列表后也可用Alt＋上下方向键。
- 新增、复制、移除和“恢复默认外观”均可撤销。“恢复默认外观”只恢复外观设置，保留案例与分类。
- 分类名称可调整，稳定分类ID保持不变。移除分类时会清除案例的相应归属；原来选择这个分类的页面保持原ID并显示空状态，管理员需重新选择，系统不会自动扩大到全部案例。
- 两个按钮可共用第一枚图标，关闭共用后恢复第二枚独立配置。SVG保留图形原色，尺寸13—24px。
- 图标文件导入到媒体库即已创建附件；修改案例库前台设置仍需点击保存。撤销设置不会自动删除媒体文件。
- 截图放大优先使用WordPress保留的原始图片地址，支持点击关闭与Esc。图片预览不是实时网站或iframe；分享与书签为窗口装饰，真实访问使用下方按钮。
- 管理器支持桌面／手机和浅／深色预览。后台预览也保留未启用案例，方便继续编辑；公开页面只显示启用案例。

## 权限和保存

中央案例库限`manage_options`管理员管理；图标导入还要求`upload_files`。图片选择使用原生媒体库。页面分类按原生页面编辑权限保存，兼容经典编辑器和Gutenberg侧栏。

案例库保存在独立option `mao_tk_zibll_toolkit_showcase`，不使用主题的`zibll_options`。每次保存都校验类型、链接、唯一ID、分类关系、数量和版本标识，并用数据库比较更新避免旧窗口覆盖新数据。冲突时保留当前草稿，提示导出后刷新合并，不自动重试覆盖。

管理器最多300个案例、100个分类，整份规范化资料最多1MiB。图片只保存附件ID和地址，不将图片二进制塞进配置。导出JSON用于备份和维护，不提供自动导入陌生文件或自动迁移生产数据。

图标链接通过WordPress安全HTTP接口获取，限制大小、协议和重定向，不传递浏览器Cookie或认证信息。SVG只接受有限图形元素和属性，移除图标库元数据，拒绝脚本、事件、实体及外部引用。复杂SVG可改用PNG；不修改全站SVG上传权限。

## 区块与旧内容

- 原区块名称仍为`maotk/demo-showcase`。新插入的默认变体明确保存`source:"central"`，读取中央案例库，分类字段为`categoryId`。
- 历史区块缺少source时按legacy处理；原cards、文字、链接、显式配色和单卡高度继续渲染，不自动覆盖为中央案例库，不改存储的旧正文。
- 新短代码`[mao_tk_showcase]`读取中央案例库；可使用`category="真实分类ID"`，以及可选`columns="2"`、`theme="auto"`。
- 旧`[maotk_demo_showcase]`与`[xt_demo_showcase]`保留1.0.7原先的六条固定预设，仅在旧别名未被其他提供者注册时接入。这些旧媒体URL可能已经失效；系统显示图片失败状态，保留其原网址。
- 想让旧短代码改用中央库，可明确写`source="central"`，或指定`category="真实分类ID"`。历史预设不会被自动导入中央库，也不会成为新案例的默认咨询地址。
- 旧主题仍提供同名区块／短代码时，Toolkit不注销或强制抢占。后台显示说明；中央案例页面模板仍可独立使用。迁移旧提供者应在备份与测试后人工处理。
- 网站按钮输出`data-link-preview="off"`，避让Toolkit文章链接增强；不改变下载、付费、商品或原生文章组件。

## 关闭、升级与回退

工作台“页面组件 → 案例展示”开关可独立关闭。关闭后不输出模块前台资源和案例内容，中央资料、附件及页面模板／分类选择仍保留；后台仍可管理。停用整个插件也不删除数据，主题原页面内容保留。

新模块在没有明确开关时默认启用，已有明确false继续保留；其他模块开关不变。需要WordPress6.3+、PHP7.4+和Zibll父主题／子主题；最低版本是设计要求，不表示所有组合均已实测。

升级前备份插件文件、数据库和案例库导出JSON。回退插件可安装原1.5.10包；新案例库仍留在数据库，旧版不会显示该功能，重新升级后可恢复。不要同时启用两个Toolkit副本。

## 当前验收范围

1.6.2修复前台弹窗第二次展开后关闭按钮锁定：使用`data-mao-tk-showcase-close`，不再使用会被子比全局AJAX监听器接管的`data-action`。保持按钮尺寸、图标和交互外观；没有解绑主题事件，也不拦截主题点赞、购买或其他功能。维护时应检查连续多次开关，而不只检查第一次关闭。

已在隔离的真实WordPress7.1.4、PHP8.5.12、SQLite Database Integration3.1.2中检查保存、媒体库、页面发布回读、分类筛选、旧区块、权限、并发冲突、按需资源、开关和停用保留；父／子主题检查使用明确标注的经典主题夹具。

1.6.1的修正依据是真实Zibll9.1主题`main.min.css`中的全局图片高度规则，只在本模块解除该限制。没有取得主题PHP源码，不宣称审阅了所有主题内部接口；PJAX、优化器及缓存按目标站点实际操作记录判断。

此前隔离测试中，IAB的WordPress可视化iframe画布为空，停用Toolkit后同样复现；页面通过原生源码编辑模式完成发布和回读，未把它记为可视化区块往返验收通过。页面标题显示与是否带侧栏使用子比本页的“页面扩展”，不会替用户改变全站布局设置。
