版本 `1.6.5`，作者 [Mao TK](https://www.maotk.com/)。提供模块工作台、“工作台欢迎提示”、独立启停的“文章顶部信息”“文章时效提示”、文章 UI 组件、正文提示框，以及后台集中管理的“页面组件 · 案例展示”。已有明确开关保持原值；新案例模块未配置时默认启用，初始案例库为空。

## 环境与状态

- 声明最低环境为 WordPress 6.0、PHP 7.4；这是代码设计基线，不代表所有高版本组合已经实测。
- 依赖 Zibll 的模块通过 `get_template() === 'zibll'` 判断父主题，因此允许目录名不同的 Zibll 子主题。父主题改名为其它目录时不会自动识别。
- 不要求 CSF 或 Zib_CFSwidget。文章模块沿用原插件的 `zib_single_before`、缩略图与计数接口用法，带存在性检查/异常后备；目标版本签名及主题 DOM 仍需在测试站验证。
- 1.6.0已在项目内隔离的WordPress7.1.4／PHP8.5.12／SQLite测试站激活并检查案例模块。1.6.1的图片高度修正来自真实子比9.1线上CSS规则核查；精确验收范围以本次部署报告为准，不推断所有子比版本、缓存和扩展均已兼容。
- 不提供网络级启用，尝试网络启用时会明确拒绝；可由管理员按单站点管理。

## 功能

后台菜单名为 **Mao TK Toolkit**，仅拥有 `manage_options` 的用户可访问和更改设置。页面显示本地图标、插件版本、父主题识别、实际环境版本、真实注册模块和当前请求的加载状态。

“工作台欢迎提示”启用后只在本插件页面显示提示。非 Zibll 环境允许保存启用意图，但状态显示“等待主题”，不运行依赖主题的模块。

“文章顶部信息”保留用户提供的 4.1.3 版前台样式，包括封面旋转/模糊、渐变、标签、动画和响应式布局。显示标题、分类/标签、作者/日期、字数/预计时间、阅读量/评论数及文章属性。未选择属性时隐藏徽标，不默认标为“热门”。

1.1.1 收紧横幅留白：桌面/平板使用统一 24px 间距，手机为 16px；移除基于视口高度的最小高度。桌面面包屑参与正常布局，标签、标题、信息和面包屑的间距一致，保留正文重叠和原有背景效果。

1.2.0 移除模块列表装饰图标，后续模块采用文字布局。控件点击/选中不再叠加外框，键盘焦点使用边框内提示。

1.3.0 将模块状态移至每行右下角，“运行中”为浅绿色标签。模块启停统一改为开关，支持点击、Space/Enter，保存期间阻止重复提交，重新读取后显示真实状态；开启意图与“运行中”可能不同，例如主题缺失或旧代码冲突时。面板采用 8px、按钮/输入框采用 6px 的轻圆角，保留简洁配色和原有全宽布局。

1.3.2 将开关固定为 56×44px 点击区，只显示滑轨，不在旁边放“已开启/已关闭/正在保存”文字。保存过程和结果使用页面右下角独立浮动提示，不占内容空间；成功提示 6 秒后收起，失败保留。工作台保留每行右下角实际状态标签；两个设置子菜单使用固定“前台模块”标题，将运行状态放到下方独立状态行。开关的无障碍名称与 `aria-checked` 继续提供当前开启状态，键盘和无 JS 原生提交仍可使用。

1.3.3 点击立即切换滑块外观，在后台保存，当前页面不刷新；实际运行状态标签与计数等待服务器确认后更新。450ms 后仍未完成才显示保存中提示，避免短请求闪烁。保存失败恢复服务器确认的状态；响应丢失先重新读取，仍无法确认时恢复先前显示并提示刷新核对。每个开关在提交期间防止重复操作，同页面的多个模块写入依次处理，其他模块可先立即响应并排队。未保存的设置、滚动位置和预览 iframe 保留。

后台保存沿用原生受权限/nonce 保护的 POST 及安全跳转，读取新请求页面中的对应模块状态，只更新本插件状态文字、nonce、计数及内置欢迎提示，不执行返回页面中的脚本，不替换设置表单。POST 最长等待 15 秒，异常后的读回最长 5 秒；这不是对多管理员并发写入的事务保证。缺少浏览器相关 API 时退回原生提交；没有 JS 时仍使用原生表单。未来自定义模块的额外动态输出需自行接入或刷新查看。

进入 **Mao TK Toolkit → 文章顶部信息** 分别设置背景、信息文字、底部信息图标三组颜色和不透明度，以及文章属性列表。点击色块展开 PS 式二维调色盘，可拖动饱和度/明度色板、竖向色相条，以及棋盘格透明滑块；支持十六进制输入、常用色块、方向键微调和 Shift 加速。底部字数、时间、日期、作者、阅读量、评论数等图标可与文字单独调色。工作台与子页面共用一个模块开关；关闭后子菜单、设置、文章属性编辑框和预览仍可使用，配置及历史数据保留。关闭后前台不加载该模块 CSS/JS。

预览使用隔离 iframe，可按文章/产品的内容 ID 或标题搜索。产品需要站点已注册 `product` 类型；不按 SKU 搜索。每次最多返回 20 项，可继续输入缩小范围，支持方向键选择、Enter 确定、Esc 收起。该选择仅用于组件预览，正式前台输出仍只作用于普通文章页。

支持真实 1280px 桌面/900px 平板/390px 手机排版宽度；画布在窄面板中按比例显示，媒体查询仍使用实际画布宽度。颜色、透明度与上下留白拖动直接更新 iframe 中的 CSS，不发送保存请求或反复加载；文章属性自动延迟刷新。保留“更新预览”按钮用于手动重载，只有“保存设置”才写入正式配置。实际内容预览不执行主题计数接口，阅读量显示“—”；样例数据明确标注。预览不写文章属性或阅读统计缓存。

### 横幅整体上下留白

1.3.4 在“文章顶部信息 → 横幅上下留白”中提供三种屏幕的上、下独立调节。拖动滑块或输入 0—200px，右侧选择对应设备即可实时查看；点击“保存设置”才影响正式文章。恢复默认按钮仅恢复这组留白，颜色和属性继续保留，仍需保存才发布。

| 屏幕 | 上方默认 | 下方默认 |
| --- | --- | --- |
| 桌面，1025px 及以上 | 24px | 12px |
| 平板，768—1024px | 24px | 24px |
| 手机，767px 及以下 | 16px | 16px |

这些默认值沿用上一版外观。旧 schema 1 配置缺少新字段时只在读取时补默认值，不自动写入或覆盖旧数据。字段为 `padding_top_desktop`、`padding_bottom_desktop`、`padding_top_tablet`、`padding_bottom_tablet`、`padding_top_mobile`、`padding_bottom_mobile`。0 为有效值，非法类型或超出范围会被拒绝。

调节作用于横幅整体上下 padding；标签、标题、信息之间原有间距继续沿用。桌面/手机原有正文重叠高度由布局额外保留，因此浏览器计算的下 padding 还会包含该结构高度。准确的导航与正文衔接仍需目标主题测试站验证。

### 横幅原位骨架与淡入

1.3.5 对桌面、平板、手机横幅统一增加自动加载过渡。常规页面在头部加载定位脚本，解析到已识别的文章结构时就完成定位；封面/图标字体尚未就绪时，真实内容仍占据原来的排版盒，分类、标题和信息行显示微光骨架。多行标题按行显示骨架，面包屑导航保持可读。

资源就绪后约 200ms 原位淡入，取消旧版的 300ms 固定延迟和从下往上的位移。缓存资源已经就绪时不人为保留骨架；失败或等待超过 1800ms 后直接释放真实文字，保留背景色。系统选择“减少动态效果”时跳过骨架与淡入。颜色、上下留白等实时编辑不会重启动画，独立预览继续保持无脚本沙箱，由父页面管理同源视觉状态。

未知主题结构或定位脚本失败仍使用原生标题；视觉辅助脚本失败时采用静态横幅。主挂钩缺失、只能在页脚补偿时，若页面已经首绘或完成解析，会保留原生页面，避免迟到的横幅挤动正文。前置本地脚本有少量首屏解析成本；主题优化器若合并/延后脚本或异步输出结构，需要在目标测试站另行验收。本版不承诺所有主题及网络条件下站点总 CLS 为零。

每个模块开关保存使用 POST、权限检查、动作 nonce、模块 ID 白名单和严格布尔值校验。设置、预览、搜索分别有独立 nonce 与参数校验，真实内容逐项验证读取及编辑权限。搜索用同源 fetch POST 返回最少字段，不提供未登录入口。写入后重新读取 Options API 验证结果。没有遥测、远程授权、自动更新或部署功能。

### 文章时效提示

进入 **Mao TK Toolkit → 文章时效提示**，设置超过多少天显示（1—3650，默认 1）、提示纯文字及可选 HTTP/HTTPS 站长联系链接。“留言反馈”指向 `#respond`；联系链接留空时隐藏，不带示例 QQ 号。只在已发布、无密码的普通文章上判断，实际经过时间严格超过设置天数才显示；更新文章后重新计算，不做定时任务或数据库扫描。

更新时间使用 WordPress 站点时区，不修改 PHP 全局时区。提示位于正文前，采用灰底、8px 圆角和插件独有 CSS 类，无 Font Awesome 依赖。优先订阅用户提供的 `zib_posts_content_before`，并用主查询、主循环中的 `the_content` 过滤器作为后备，同请求只输出一次。前者尚无目标 Zibll 源码可核实，准确位置仍需目标测试站检查。

1.3.1 在“温馨提示”前使用用户提供的 `hint.svg` 铃铛图标，正式文章和后台预览共用渲染及 CSS。图形存于插件本地，以 CSS mask 继承提示文字颜色，适应亮/暗背景；不新增模块列表装饰图标或图标字体。运行 SVG 去掉 XML/外部 DTD 和编辑器元数据，保留全部路径。

设置输入防抖更新隔离样例预览；演示日期明确标注，不读取真实文章或保存配置。关闭模块后仍可设置、保存与预览，前台不输出提示或加载对应样式。检测到原 `article_time_update` 已挂到同名主题 hook 时阻止新提示并显示后台说明，不自动修改主题或移除别人的回调。若旧提示用了其它函数名，需要自行核对是否重复。

## 使用和安装方式

以下安装方式适用于目标站点。1.6.0的隔离测试与1.6.1的真实子比站点验收分别记录；生产升级须按当次授权执行。

1. 在目标 WordPress 测试站点备份数据库，并确认 PHP 与 WordPress 满足声明基线。
2. 上传发行 ZIP，或将插件目录放在测试站点的 `wp-content/plugins/`。
3. 单站点启用后，打开 **Mao TK Toolkit**，先核对主题识别和环境版本。
4. 启用“工作台欢迎提示”，刷新验证“运行中”和提示；再停用，验证状态与提示消失。
5. 在 Zibll 子主题、非 Zibll 主题、不同管理员配色和移动端环境中分别回归。
6. 进入“文章顶部信息”，先在关闭状态下试桌面/手机预览，再保存设置、启用模块并查看测试文章。
7. 如果检测到独立版顶部信息插件仍在运行，本模块拒绝接管前台，并在子页面提示；自行停用独立版后再试，不自动停用或移除其他插件的 hook。
8. 在“文章时效提示”中先预览，再保存并开启开关；检查一篇近期更新和一篇超过阈值的测试文章。若主题已有原来的 `article_time_update`，先确认旧代码位置并自行移除旧挂钩，再启用新模块；本插件不会改主题核心。

横幅只作用于已发布、无文章密码的普通文章页；其他状态保留主题原有页面。浏览器 JS 加载失败或找不到预期主题容器时，保留原生标题。整页缓存/CDN 可能继续返回旧内容，开关后需按站点缓存策略刷新。

如果服务器禁止直接访问 Markdown 文件，页面内“使用说明”仍可阅读；完整文档也可从插件源码目录阅读。

## 模块开发接口

模块实现 `MaoTK\ZibllToolkit\Module`，提供以下方法：

| 方法 | 作用 |
| --- | --- |
| `id(): string` | 唯一 ID，必须匹配小写字母开头、后续小写字母/数字/连字符，最长 64 字符 |
| `name(): string` | 管理页名称，渲染时会作为纯文本转义 |
| `description(): string` | 管理页说明，渲染时会作为纯文本转义 |
| `requires_zibll(): bool` | 是否必须识别到 Zibll 才允许启动 |
| `boot(): void` | 模块被启用且依赖满足时执行；在此注册实际业务钩子 |

在插件启动前订阅 `mao_tk_zibll_toolkit_register_modules`，回调接收 `ModuleManager`，调用 `$manager->register($module)`。注册发生在 `after_setup_theme` 优先级 20 的启动过程中；需提前订阅，不能等此阶段结束后才注册。

管理器拒绝重复 ID 和非法 ID。扩展模块默认关闭，五个内置正文组件默认启用；仅注册真实可用实现。`mao_tk_zibll_toolkit_dashboard_content` 是本插件管理页专用的内容输出 action，可参照欢迎模块接入。

`boot()` 中的 `Throwable` 会被逐模块捕获，一个模块失败仍继续启动后面的模块。页面内容 action 发生异常时，工作台会显示通用错误并继续渲染其余页面区域。它不能隔离进程退出、内存耗尽，也不接管各模块后来注册的任意 WordPress 业务回调；一个内容 action 回调抛出异常后，本次尚未执行的同 action 回调不会自动恢复。模块自身仍须处理业务回调错误。

注册扩展的 action 若抛异常，已注册模块仍处理，页面提示注册异常；异常之后尚未运行的注册回调不保证执行。不把异常堆栈发送到浏览器或系统日志。

## 数据与生命周期

开关 option 为 `mao_tk_zibll_toolkit_settings`，结构是 `schema_version: 1` 和 `modules` 的 ID→布尔值映射。默认没有开启的模块，不设置跨请求静态选项缓存。

文章模块配置独立存储于 `mao_tk_zibll_toolkit_top_info`。新键不存在时兼容读取旧 `moxing_top_info` 中的颜色和 `footer_tabbar` 属性列表，读取/预览不会自动迁移写入；显式保存才创建新键，旧 option 不变。旧 `mx_top` 不自动开启 Toolkit 模块。

时效提示使用 `mao_tk_zibll_toolkit_article_freshness`，schema 1，字段为 `days`、`message`、`contact_url`。阅读和预览不创建该选项；只有明确保存才写入，关闭模块保留。不会修改文章更新时间、文章内容、旧横幅配置或属性；没有 cron、外部请求和自动迁移旧函数中的硬编码链接。

不透明度新增 `bg_opacity`、`text_opacity`、`icon_opacity` 三个 0—100 的整数；旧配置缺少背景/文字透明度时为 100，图标缺省继承旧文字颜色和透明度，0 为明确的全透明。`icon_color` 让底部信息图标单独调色。颜色键仍存三/六位十六进制，信息文字及图标在渲染时组合为 RGBA，背景/封面通过一个背景层控制整体不透明度，避免同色层重复叠加。现有颜色、属性及原始旧配置不自动改写。

文章属性优先读取 `_mao_tk_toolkit_top_info_property`，没有新值时读取旧 `article_property`。编辑文章只写新键；选择“不显示属性”保存新的空值，旧值仍保留，避免恢复旧徽标。历史属性即使不在当前列表，也会保留显示/选择。旧阅读统计缓存 `_moxing_top_info_reading_stats` 兼容读取；模块开启后正常保存文章会更新新缓存 `_mao_tk_toolkit_top_info_stats`。缓存缺失在内存中计算，公开读取与预览均不写缓存。

激活时只 `add_option`，不覆盖已有数据。默认不自动清理数据：停用、删除插件文件都保留该 option，方便重新安装后恢复。由于 V1 没有 cron、重写规则或其它需要清理的资源，没有创建空的停用/卸载 hook。未来若增加这些资源，需同时设计对应清理逻辑。

不认识的 schema 或异常存储类型会使模块和写入暂停，页面报告配置异常；不会静默重置原有值。后续应在测试与备份后修复配置来源，V1 不提供一键破坏性重置。并发管理员同时写入多个模块配置仍可能产生 Options API 的最后写入覆盖，V1 不承诺数据库事务隔离。

## 后台设计

继承 WordPress 系统字体和原生按钮配色，内容不设固定最大宽度，沿用后台可用区域和左右边距。面板、按钮和提示框采用轻圆角细边框，不添加装饰性彩色边条；运行标签使用浅绿色，开关沿用后台强调色。使用说明合并为侧栏中一处紧凑的三步说明，不再提供顶部重复入口或底部折叠区。主色优先读取 `--wp-admin-theme-color`；变量不存在时，从当前管理员注册配色的第三个颜色获取经过 `sanitize_hex_color` 处理的启发式 fallback，再回退系统 `Highlight`。原生 `.button-primary` 始终沿用 WordPress 自己的实际配色。第三方配色的预览色数组不保证代表其真实强调色，需在该配色下验证。

后台 CSS 限定在 `.mao-tk-toolkit` 内；只在工作台及登记的子菜单 screen hook 加载。文章前台资源只在模块启用且文章适用时加载，字体来自插件本地。控件有可见焦点、文本状态、加载/错误反馈和移动端适配；禁用 JS 仍能通过原生表单保存设置，设备预览需要 JS。预览文档的独立 CSS 只进入 iframe。

模块列表不再预留装饰图标列。按钮/输入框的选中与焦点使用同一条边框，键盘焦点在边框内增强，不额外加外围框。调色盘使用组件内 CSS 渐变和 Pointer Events，没有浏览器原生颜色弹窗或外部选色依赖。

侧栏菜单采用用户提供的 Expand.svg 图形：运行文件为 `assets/images/expand.svg`，保留原图形路径，去除 XML/外部 DTD 与编辑器元数据，使用 20px 尺寸和 black 填充，通过 WordPress 原生 SVG data URI 菜单接口按当前配色着色。页首品牌图标保持原样，菜单图标不再使用扳手。

## 1.5.8 管理界面与链接优化
