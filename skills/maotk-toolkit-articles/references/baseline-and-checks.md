# 当前基线、迁移与验收

## 已知可复用基线

2026-10-30已核对：Toolkit1.5.7、子比9.1、WordPress7.1.4。代码框中性顶栏与原生代码底色区分，下方正文间距20px、手机18px；由插件提供，文章不补CSS。不是对后续版本的永久兼容承诺。

| 项目 | 模块ID / 条件 |
| --- | --- |
| 代码 | `article-ui-code`，根组＋`mtk-code-wrap` |
| 链接 | `article-ui-link-preview`，根组＋普通HTTP/HTTPS链接 |
| TAB | `article-ui-tabs`，根组＋`mtk-native-tabs` |
| 文章卡片 | `article-ui-postsbox`，根组＋`mtk-native-postsbox` |
| 阅读/图片/FAQ/变量复制 | `article-ui-reading`，根组＋`mtk-article-reading` |
| 正文提示框 | `article-note`，可用 `maotk/note` 提供者；不要求第一批根组 |
| 推荐/外部工具入口 | Toolkit1.7.0+ 的 `article-ui-resources`；原根组追加 `mtk-legacy-resources` |

前五项接入需要WordPress6.2+ HTML API，提示框新能力需要6.3+。Toolkit通过父主题目录 `zibll` 识别依赖，支持子主题。原生业务能力还需按具体模块核对。

当前能力在未设置开关时默认启用，已有明确false会保留。不要因为“默认开启”就声称某个站点实际开启。原插件提示框提供者优先，Toolkit只在安全条件下提供原块，不能重复注册。

可参考的已上线页面：

- [正式教程31](https://www.maotk.com/order-email-manager-tutorial/)：正文、原生标题/目录、19张原生图片、三种提示、示例代码、变量复制和七项FAQ。
- [验证文章145](https://www.maotk.com/toolkit-article-ui-verification/)：宽长代码、链接、TAB、真实文章卡片和五种提示配置。

这些是参考，不是每篇文章的默认内容/ID。没有访问当下页面时，只能称为历史验收。

## 本机维护入口（可选）

存在时读取实际版本和接入文档，不依赖这些路径才能写出标准结构：

- 若工作区有宿主源码，读取 `plugins/mao-tk-zibll-toolkit/article-ui/README.md`、`article-ui/note/README.md` 及对应CSS/JS/类文件，以实际路径为准。
- 已有文章的原始区块源、迁移/验收报告与当前保存回读应由当次任务提供或获取；不要假定下载者的磁盘位置、站点账号、附件或文章编号与示例站相同。

旧manifest/README的历史部分可能仍写“折叠未接入”“教程31未迁移”。以实际源码、版本和最新迁移记录对照，不把旧说明当成当前事实，也不为纠正文档顺带修改线上插件。

## 样式不生效时

按症状定点检查，不反复试写CSS：

1. 目标站点、插件版本/开关、Zibll依赖和提示框提供者是否正确。
2. 存储源码是否存在原生根组、所需组件类；前台是否由插件生成相应启用属性。**只加载CSS不等于已接入。**
3. 是否仍存有旧style/script或旧浮层。四组件运行时会保守避让内嵌资源；先备份并盘点归属，不能为通过检查而盲删业务代码。
4. 原生预览是否使用当前新稿；1.5.5修复过“按ID重取旧发布正文”的资源扫描问题。遇旧版本时不手写启用属性掩盖故障。
5. 样式是否被旧文章资源覆盖，是否有重复ready/浮层。截图和数据分别记录，问题属于宿主时交给插件任务处理。
6. 后台提示框颜色已保存但某篇不变时，检查 `maotk/note` 的 `maoTkNoteVisual.light/dark`。单块优先级最高；普通文章应继承后台，不能把单块覆盖误报成后台保存失败，也不应为对比度擅自添加颜色覆盖。
7. 代码颜色看似不随主题时，先看代码块主题是否留空、语言是否正确，再对照子比的浅/深高亮设置。纯文本中的 `#` 被generic识别为注释是语言选择问题，改为raw；不能靠覆盖token颜色修复。1.5.7实测浅色Enlighter、深色Dracula来自当时站点设置，不是技能要固定的名称。

## 新文章/改文验收

- 改写旧文先按 [完整保留规则](rewriting-existing-articles.md) 完成逐项对应表；检查真实步骤、全部教学图片、完整代码、推荐及推广参数，不能以摘要代替实操。下载用途同步核对正文、原生块与SEO。
- 保留当次要求保留的标题、下载、封面、SEO、图片和已完成章节；真实ID与地址已核对。
- 源码检查器通过；不带前台运行时属性，不把模板占位符发布出去。HTML代码演示先转义。
- 确认主题标题/目录仍原生；FAQ按钮与面板唯一关联、互斥展开、答案无截断，目录能定位所用内容。
- 图片加载并有ALT/说明，边界可见且不改原图文件；实际打开主题大图。
- 代码工具/原文、实际TAB、链接打开/复制/预览、卡片跳转按本篇使用范围验证。
- 窄屏检查页面不横向溢出；宽/长代码只在框内滚动，提示、表格和FAQ可读。
- 明确区分“观察到复制完成提示”和“独立核验剪贴板内容”。
- 保存后读回正文，公开更新则检查公开页。原生编辑器往返未完成时如实标注，静态块配对检查不等于编辑器验证。

源码、实际页面、自动检查与尚未验证项分开报告。不要为了写作去改全站noindex、邮件发送、购买权限或账号角色。
