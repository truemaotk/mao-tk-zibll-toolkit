# 图片、封面与 Rank Math 默认流程

版本：SKILL 1.2.0；维护日期：2026-11-01。用于新文章制作，以及已有文章中新增加或明确要求重做的素材和 SEO。用户当次要求优先；不把文章更新扩大为批量换图、改主题或全站 SEO 设置。

## 默认选择

| 对象 | 默认做法 | 保留与验收 |
| --- | --- | --- |
| 新文章封面、照片、普通插画 | 优先在 [towebp.io](https://towebp.io/) 转 WebP，Quality 80%，Size x1 | 保留原文件；100% 查看并检查手机裁切，清晰度不够提高质量或改无损 |
| 后台界面、小字、代码、步骤箭头等精度敏感截图 | 优先真正的无损 WebP，保留原尺寸 | 原始截图和标注稿单独保留；逐字检查关键字段和标注 |
| 已经合格的 WebP、既有文章封面 | 复用，不反复转码、不擅自替换 | 改写旧文先逐项核对原图片与步骤，再决定是否新增 |
| SVG 图标、动图 | 保留合适的原生格式和动画 | 不为统一扩展名而栅格化图标或丢失动画 |

“自动”指 Codex 在本次可用工具和授权范围内执行这套流程，不代表 Toolkit 本身提供自动转图、生成封面或代填 SEO 的功能。没有生成、转换、上传或后台编辑能力时，完成可做部分，交付文件和准确的待办；不宣称已上线。

## 图片：先保留原稿，再生成上传副本

1. 先清点文章已有图片、特色图像和附件资料。按用途建立“原稿 → 标注稿 → 上传版 → 附件 ID → 插入位置”对应记录，避免旧图丢失、步骤错位和重复上传。
2. 新截图从当前真实界面拍摄，不生成假 UI。截图工具支持时，原图和标注图用原分辨率无损 PNG；若工具只提供 JPEG，保留真实源格式并说明，不能把转存 PNG 称为恢复无损。标注只加必要的红框、箭头和步骤号。发布前核对敏感信息已按任务要求处理，不把账号资料、原始凭据图装进公开下载包。
3. 封面与照片优先使用用户指定的 **https://towebp.io/**。读取实际界面，设置 **Quality 80% / Size x1**，再 Add Files、转换、Download All。x1 表示保持尺寸；80% 是编码质量起点，不是缩成原图的 80%，也不是保证减少 80% 文件大小。未来界面变化时按实际控件操作，不硬猜坐标。
4. 文字密集或需要保留像素的截图走真正无损。2026-11-01 的 towebp.io 页面只有 Quality 和 Size，未提供独立无损开关，**不能把 Quality 100% 当作无损**。可使用当前已可用、能显式选择 lossless 的本地编码器；例如已有 Pillow 时使用 `lossless=True`，已有 cwebp 时使用 `-lossless`。不为这一步擅自安装软件。无法可靠产生无损 WebP 时保留 PNG，并在交付中记录例外，不以有损结果冒充无损。
5. 转换后检查实际扩展名、文件格式、宽高与大小；用原尺寸 100% 查看关键文字、红框、边缘和透明部分。普通 80% 结果出现明显失真时，重新从原稿以 85%／90% 或无损输出，避免对压缩后的副本继续压缩。尺寸调整仅在用户要求或目标版位确有需要时单独决定并记录。
6. 上传前用稳定的英文语义文件名，例如 `article-slug-cover.webp`、`article-slug-step-03-settings.webp`。上传到 WordPress 后填写真实附件标题、ALT、必要的图注与描述，再把真实附件 ID 与 URL 写入原生 Image 块。ALT 描述图片内容与用途，不堆关键词、不把文件名当 ALT；图注解释该图对应的动作或结果。
7. 使用目标 WordPress 实际支持的图片序列化；不要为通过检查随意改写原生区块保存格式。前台检查最终图片有真实尺寸或正确比例占位、可打开大图，窄屏没有溢出；图片边框和圆角调用 Toolkit，不在文章写 CSS。

转换来源核对：[towebp.io 当前界面](https://towebp.io/)；[Google cwebp 文档](https://developers.google.com/speed/webp/docs/cwebp)说明有损质量与显式无损模式的区别。网站声称在浏览器本地转换，不把该宣传当作已完成独立网络隐私审计。

## 封面：新文章默认生成，旧文章保留已确认稿

1. 新文章默认制作一张专属封面；已批准的旧封面继续用。只有用户要求换封面，或明确发现图片不可用时，才处理替换；删除旧媒体需要单独符合任务授权，替换入口不等于永久删除。
2. 优先看当前博客已确认封面的系列风格与真实版位。延续干净的 3D 教程插画、明快配色和主题相关物件，但构图、主物件与视觉焦点随文章变化，不复制另一张封面。比例以当前主题实际显示为准，无具体版位时可从现有系列的 4:3 横图开始。
3. **四周留至少约 10%–12% 安全边距**，文字和关键图形远离边缘，兼顾首页卡片、手机和分享缩略图裁切。短主标题优先 1–2 行，必要时仅一条简短副文案；不在四角堆品牌、版本号、小字和标签。
4. 使用当前可用图像生成工具；有 imagegen 技能时按其要求执行。封面是插画，不把生成的后台或支付画面当成教程实证。生成后检查中文错字、图标、裁切和缩略图识别度；工具不可用时说明待生成，不用假文件冒充。
5. 保留生成原稿，上传副本按上面的 WebP 80% / x1 流程处理并验收。设置为当前文章特色图像，检查主题其他封面来源有无覆盖。用户说“我自己上传”时只交付封面和 SEO 素材，不代为设置。

## Rank Math：逐字段保存，并检查真实输出

先读取目标文章现有 SEO 与全站限制，保留有效配置和已发布 URL。通过对应站点连接器或实际 Rank Math 编辑器操作；不能操作时交付字段表，不宣称已经填写。

| 字段 / 位置 | 默认填写与检查规则 |
| --- | --- |
| 文章标题 | 清楚说明读者任务，不重复 H1；更新旧文默认保留原题，必要修改以任务范围为准 |
| Focus Keyword | 选择与正文一致的一个主关键词，必要时少量相关词；保存为实际标签项，不能只把文字留在输入框未提交 |
| Edit Snippet → Title | 用自然中文包含主关键词和用途；按当前预览检查长度，避免关键词、站名重复；不强制追求打满评分 |
| Edit Snippet → Permalink | 新文使用简短稳定的英文 slug；已上线文章保留原 slug，除非用户明确要求迁移并处理跳转 |
| Edit Snippet → Description | 一两句说明本文解决什么、适合谁和涵盖步骤；自然包含关键词，约 80–120 个中文字可作起点，最终看预览是否截断，不作硬性排名标准 |
| WordPress 摘要 | 独立写简洁内容摘要，可与描述相近；不要把下载文件名、HTML 或整篇正文当摘要 |
| 分类与标签 | 沿用站点实际分类，选择主题相关标签，避免为每篇建立大量同义项 |
| 特色图像、Social → Facebook / Twitter | 设置并检查正确封面、分享标题和描述；已有继承正确时复用，不制造重复配置，核对实际 OG / Twitter 输出 |
| Advanced → Canonical | 无特殊情况保持正确默认自引用；更新旧文不要无故覆盖或指向别的文章 |
| Advanced → Robots | 读取并保留现有站点和文章策略，不擅自解除全站 noindex；若任务确需变更，按原有权限边界处理 |
| Schema | 教程通常沿用当前 Article / BlogPosting 设置；不伪造评价、产品价格或作者资料，不因有可见 FAQ 就擅自叠加重复 FAQ Schema |

实际流程：读取已有值 → 填写有变化的字段 → 保存文章 → 重新进入编辑器回读 → 打开公开页核对 `<title>`、description、canonical、robots、OG、Twitter 与适用结构化数据。**后台显示已保存不等于前台输出正确。** 如果主题或插件导致 head 缺项，记录实际结果并指出应修哪一层；不在正文插入 meta、CSS 或 JS，也不顺带改全站 SEO。Rank Math 分数仅作辅助检查，不能等同搜索收录或排名保证。

## 交付记录

素材记录至少包含：文件名、用途、原稿位置、输出格式、宽高、压缩模式、质量值（无损不写“80% 无损”）、Size、附件 ID / URL、ALT、图注和插入位置；只记录本次相关信息，不将本机凭据或私有原稿发布到 GitHub。

交付时简要说明封面是否生成／设置、WebP 选择与例外、SEO 字段是否保存回读及公开页结果。授权发布时直接完成并核对；未授权发布时保持草稿或交付素材。本流程本身不扩大网站、账号、上传或发布权限。
