# 继续使用子比原生功能的组件

这些模块不需要套一份“美化HTML”。优先从当前Gutenberg插入器生成；需要代码编写时，复用对应版本真实保存的区块/短代码，不臆造属性。

| 模块 | 后续文章的处理 |
| --- | --- |
| 文件下载 | 原生 `Zibll:文件下载` / `zibllblock/download`，绑定实际附件；保留校验、权限和付费处理 |
| 隐藏/付费内容 | 原生隐藏短代码及当前文章的付费设置；不恢复已撤回的卡片美化 |
| 商品 | 原生商品块或 `[productbox id="实际编号"]`，从真实商品读取资料和跳转；宽度曾有单篇草稿，未成为当前Toolkit通用能力 |
| 文章列表 | 原生 `Zibll:文章列表`，配置真实分类/专题/排序/数量；不复制AJAX结果冒充动态列表 |
| 视频 | 原生 `Zibll:视频` / `zibllblock/dplayer`，真实视频直链或媒体 |
| 视频剧集 | 原生 `zibllblock/dplayerfeatured`，每集真实地址与标题，主题管理选集 |
| 超级嵌入 | 原生 `zibllblock/iframe`，有效可嵌入页面/iframe；网页URL不是视频文件直链 |
| 剧集嵌入 | 原生 `zibllblock/iframeseries`，保持 `.switch-iframe` 的原生切换 |
| 标题/目录 | 编辑器H1、子比标题块、H3及主题目录，均不接管 |
| 图片查看 | 主题原生大图，不新建图库脚本 |

亮点、引言、按钮组、幻灯片、上下无缝图及弹窗没有因此成为新的Toolkit封板组件。需要时使用当前原生模块；不借历史综合演示的CSS/JS恢复一套未接入样式。无缝图的历史选择为上下方向，但仍须以当前真实模块配置为准。

## 权限与状态

- 登录可见：使用原生 `[hidecontent type="logged"]…[/hidecontent]`，不要只隐藏DOM。
- 付费阅读：在**当前付费文章**设置原生模式、价格和权限，再插入对应隐藏内容，例如已核对的 `type="payshow"`。不能凭短代码或静态购买按钮宣称权限已经生效。
- 下载/商品使用真实对象编号，不能照搬教程附件38、演示商品80或文章31等历史编号。草稿商品的管理预览可见，不等于访客可购买。
- 会员、未购买/已购买等跨身份状态需要真实权限验证；仅展示样子时明确标注“只读外观示例”，不伪造付款成功、订单或鉴权结论。
- 普通写作任务不需要修改账号身份、执行付款或遍历全权限矩阵。按实际使用范围验证，不把曾经的全组件演示要求变成每篇文章的负担。

## 媒体保存与测试

为代码文章引用原生媒体时，使用当前主题实际保存结果。历史演示曾因额外iframe属性或播放器结构与主题save不同而校验失败，不能沿用未验证的前台DOM。

确认真实地址、附件/文章/商品ID、剧集顺序与封面，再实际测试所用播放/选集/嵌入切换。保留资源出处和使用权；不要把官方演示视频或旧测试视频当作新文章的正式素材。
